围棋背谱闯关 v2.8.0 自动结算与对战记录版

安装
使用同包名 org.weiqi.memory、同签名覆盖升级。不要先卸载或清除数据。
建议先导出 JSON 备份。应用保持离线，无网络权限。Android 原生 DEX 与 v2.7.0 完全相同。

自动判胜负
1. 双方连续停一手后，自动结算、语音反馈，并保存到“记录 → 对战输赢”。
2. 轮到孩子落子时，可用“判胜负”提前结算，先弹确认，防止误触。
3. 认输会直接记录确定的负局。分数采用面积计分：活棋子 + 围住的空点，白加 7.5。
   已提走的棋子不额外加分；双方交界的空点为中立点。
4. 本地算法先检查两眼可证活的棋块，再对其包围的小区域做有节点数/时间/深度限制的读棋。
   不把“未证明活棋”当成“死棋”；只有小区域中先让被围方走也无法避免提走时，才自动移除。
   劫相关、搜索超限、大区域或其他无法确认的棋块留在盘上计分，结果标为“估算待复核”。
5. 这不是 KataGo、GNU Go 或职业级死活裁判，不保证复杂劫争、双活、未完局的判断。
   程序不能保证发现所有有争议情况。家长仍可复核，或点击“继续下”把棋下清楚。
6. “家长复核”可修改死子标记；确认后替换该局记录，不增加一局。
   “继续下”会撤回本局的已结算记录；下完再记。仍在下的局不计胜负。

记录
“记录”页分为“闯关记录”和“对战输赢”，互不覆盖。
保存最近 100 局的胜/负/和、日期、棋盘大小、所执颜色、最终选择的难度、手数、分数、分差、
结算方式和估算标记。胜率=保存的获胜局数/保存的全部已结算局数（包括估算局和和棋）。
筛选：全部、赢了、再加油、估算；翻页查看；点击一局语音读结果并展开详情。
本机存储、原生备份、JSON 备份都包含这些字段。旧版没有保存的分数不会凭空补出。
导入备份按 id + 更新时间合并，保留较新修正，并记录撤回标记，避免旧备份复活已撤回的结算。
没有云端同步；卸载/清除应用数据会丢失本机记录。应保留外部 JSON 备份。

语音与布局
保留选定的 B 音色（Matcha，sid=0，speed=.96），新增 22 条离线配音；旧音频不变。
标题可点击朗读；语音开关统一控制，静音时自动结果也不播报。
保留全棋盘横屏布局。棋盘上方无菜单；结果和操作在右侧。对战记录自动分页，无须滚动整页。

验证范围
- test_auto_scoring.cjs：保守计分/死活/贴目/中立点/劫与搜索超限/对称性/9、13、19路；11组测试。
- test_battle_rules.cjs：原有提子、自杀、重复局面、悔棋、三个难度的落子合法性。
- test_auto_results.py：使用 APK 内实际资源、强制离线的桌面 Chromium，原生存储和音频桥为模拟。
  检查自动结束、撤回、更正、无重复、过滤、备份、重启以及9种横屏尺寸x4种界面状态。
- test_upgrade_28.py：用实际 v2.7.0/v2.8.0 APK 网页代码及复制的模拟原生存储验证升级。
- validate_release.py：APK v2 签名、包名/版本/横屏、无网络权限、DEX校验、资源路径/音频对齐等。
- 新音频都执行解码数值检查；非逐句人工听审。
尚未在 Android 真机/模拟器上安装测试，不等同于真机跨版本升级验证。

源码构建
改网页：编辑 web-src/*.js 或 assets/index.html/app.css，然后 node transpile.cjs。
本次不修改原生层，classes.dex 复用 v2.7.0 已可用原生文件。
需要重编原生层时，设置 ANDROID_JAR 和 D8_JAR 并执行 build_native.sh。
package_apk.py 使用 private-signing 下的原签名。此源码包不含私钥，需要从先前私有备份恢复。
不能生成新签名来冒充原应用更新。源码包也不含语音模型、字体或安卓SDK。
assets 下的棋谱及生成音频已全部齐备；重建不必重新生成配音。
